# How the T3 talks to the Jeep app

The app connects to the T3 over Bluetooth Low Energy using the Nordic UART service, the same one most
ESP32 BLE UART examples use. Open the app in Bluefy on the iPhone (Safari can't do Bluetooth), go to
**Live** and tap **Connect**.

| | UUID |
|---|---|
| Service | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` |
| RX: app writes to the T3 | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` |
| TX: T3 notifies the app | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` |

Advertise the name **Jeep T3** (the app looks for names starting with `Jeep`).

Every message is one line of JSON ending in `\n`. Lines can be split across notifications any way you
like; the app joins them back up. Keep each line under about 400 bytes.

## T3 to the app

**`hi`**: send once after the app says hello.

```json
{"t":"hi","fw":"0.1"}
```

**`live`**: 2 to 5 times a second while the engine runs. Leave out anything you can't read; the app
shows a dash for it.

```json
{"t":"live","kmh":72,"rpm":1850,"boost":9.5,"ect":88,"iat":14,"v":14.1,"load":45,"lph":7.2,
 "trip":{"km":12.34,"l":1.02,"s":845,"idle":120}}
```

| Field | Meaning |
|---|---|
| `kmh` | speed, km/h |
| `rpm` | engine speed |
| `boost` | boost in psi (MAP minus barometric) |
| `ect` | coolant temperature, °C |
| `iat` | intake air temperature, °C |
| `v` | battery voltage |
| `load` | calculated engine load, % |
| `lph` | fuel used right now, litres per hour (the app works out L/100 km from this and `kmh`) |
| `trip.km`, `trip.l`, `trip.s`, `trip.idle` | this trip so far: distance km, diesel litres, seconds driving, seconds idling |

**`trip`**: when a trip ends (key off, or when the app asks). Keep finished trips until the app sends
`ack` with the same `id`, so trips driven without the phone still reach the log next time.

```json
{"t":"trip","id":"t42","km":18.6,"l":1.9,"s":1530,"vmax":102,"idle":95,"t1":1761090000000}
```

`s` and `idle` are seconds. Give `t1` (end time, epoch milliseconds) if the T3 knows the time: the app
sends it in `hello`. Otherwise send `ago`, the seconds since the trip ended, or nothing, and the app uses
the time it received the trip.

## The app to the T3

```json
{"c":"hello","now":1761090000000,"app":"1.0.0"}   on connect: the time, so trips can be stamped
{"c":"trips"}                                      send any trips not acked yet
{"c":"ack","id":"t42"}                             that trip is in the Jeep log; forget it
{"c":"reset"}                                      start a new trip
```

The app writes in 20-byte pieces, so join RX writes until you see `\n` too.

## Setup and status (T3 1.0)

The T3 code is in [firmware/T3/T3.ino](firmware/T3/T3.ino). Heep's **T3 setup** sends:

```json
{"c":"cfg","wifi":["home name","home password","hotspot name","hotspot password"],"u":"<web app url>","k":"<key>","fc":1.0}
{"c":"status"}
```

The T3 keeps them in flash and answers `{"t":"cfg","ok":true}`, then a `hi` with its status:

```json
{"t":"hi","fw":"1.0","obd":true,"nets":2,"sheet":true,"queued":3,"up":"sent 3 trips","upAgo":120,"fc":1.0,"dc":1.0,"totKm":1520.4}
```

With trips waiting, it looks for a saved network (home first, then the hotspot) and sends them straight to
the sheet as `put` operations on the trip tab, with the same IDs Heep uses, so a trip that arrives both ways
is only kept once.
