# How the T3 talks to the Jeep app (protocol 2, T3 firmware 2.7)

Two ways in, same messages:

- **Bluetooth LE** (Nordic UART service), from Heep in **Bluefy** (Safari can't do Bluetooth). Name **Jeep T3**.
- **The relay** (MQTT over TLS, `broker.emqx.io`), when the T3 is on Wi-Fi (your hotspot). Works in any browser.

| | UUID |
|---|---|
| Service | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` |
| RX: app writes to the T3 | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` |
| TX: T3 notifies the app | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` |

Every message is one line of JSON ending in `\n`, sent in 20-byte pieces both ways; each side joins them back up.

## The relay

Channel names come from your sheet key: `heep/<first 16 bytes of SHA-256("heep-live:" + key), hex>/live` (T3 → app)
and `.../cmd` (app → T3).

- **T3 → app** (live numbers and every reply): `{"e":"<base64>"}` where base64 is a 12-byte random nonce, then the
  message encrypted with AES-256-GCM, then the 16-byte tag. Key = SHA-256(`"heep-enc:" + sheet key`).
  (T3 1.4/1.5 sent plain `live` lines; Heep still reads those.)
- **App → T3**: `{"n":<ms>,"m":"<the command JSON as a string>","h":"<hex HMAC-SHA256(sheet key, n + "|" + m)>"}`.
  The T3 ignores it unless the HMAC matches, `n` is newer than the last command it took (kept across restarts),
  `n` is within 10 minutes of its clock, and it knows the time. Wi-Fi passwords, the sheet link/key and the track
  store link/key are refused over the relay: they only go over Bluetooth.

## T3 to the app

**`live`** twice a second (Bluetooth), once a second (relay). Anything unknown is left out.

```json
{"t":"live","kmh":72,"src":"obd","rpm":1850,"boost":9.5,"ect":88,"iat":14,"v":14.1,"load":45,"lph":7.2,
 "g":4,"lat":56.246500,"lon":-120.847600,"gkmh":71.8,"hdg":87,"hdgAge":0,"sats":9,"inv":14,"hdop":0.9,"ot":-12.5,
 "tp":0,"pg":0,"btn":"3S","bn":12,"nano":"ok","sd":1,
 "trip":{"id":"t42-1","km":12.34,"l":1.02,"s":845,"idle":120,"vmax":96,"gkm":12.30}}
```

| Field | Meaning |
|---|---|
| `kmh`, `src` | speed the T3 is using and where from (`obd` or `gps`) |
| `rpm boost ect iat v load lph` | iCar values (boost psi; ect/iat °C; v battery V; lph fuel L/h) |
| `g` | GPS state: 0 no data, 1 data but not NMEA (baud), 2 searching, 3 2D fix, 4 3D fix |
| `lat lon gkmh` | only with a valid fix |
| `hdg`, `hdgAge` | last trusted GPS course (°) and seconds since it was trusted (moving); over 3 = stopped |
| `sats inv hdop` | satellites used / in view, HDOP |
| `ot` | outdoor °C (only when the probe reading is fresh) |
| `tp` | trip paused 1/0 |
| `pg` | screen showing |
| `btn bn` | last wheel button (`3S`, `1L`, `2R`) and count of presses |
| `nano` | wheel link `ok` / `lost` / `none` |
| `sd` | card logging 1/0 |
| `trip` | this trip so far (gkm = length of its GPS track) |

**`hi`** answers `hello` and `status`: `fw`, `proto`, `obd`, `queued`, `up`, `upAgo`, `totKm`, `upd`, `wifi`, `seen`,
`scrh` (screens fingerprint), `scrn`, `trk`, and every setting (see `settingsJson()` in `settings.ino`; no passwords or keys).

**`diag`** answers `diag`: everything Diagnostics shows (`gps`, `temp`, `nano`, `wifi`, `ble`, `sd`, `up`, memory, reset reason, clock source).

**`trip`** (Bluetooth only), after `trips`: a finished trip not acknowledged yet:
`{"t":"trip","id":"t42-1","km":18.6,"l":1.9,"s":1530,"vmax":102,"idle":95,"gkm":18.4,"t0":...,"t1":...,"a0":[lat,lon],"a1":[lat,lon]}`

**`cfg`** `{"t":"cfg","ok":true}` after settings. **`scr`** `{"t":"scr","ok":true,"h":"<fingerprint>","n":10}` or `{"ok":false,"why":"..."}`.
**`scrd`** `{"t":"scrd","i":0,"n":10,"d":"<screen text>"}` one per screen after `getscr`.

## The app to the T3

```
{"c":"hello","now":<ms>,"app":"1.1.0"}  on connect: the phone's time (the GPS's wins)
{"c":"status"}                           send hi
{"c":"diag"}                             send diag
{"c":"trips"}                            send finished trips not acked yet (Bluetooth)
{"c":"ack","id":"t42-1"}                 that trip is in the Jeep log: forget it
{"c":"trip","do":"pause|resume|end|start"}   the trip state machine (same one the wheel buttons use)
{"c":"reset"}                            old name for trip end
{"c":"act","a":"next|prev|home|mark|pause|end|sleep|bright|peak|send"}   same actions as the wheel buttons
{"c":"page","i":2}                       show screen 2
{"c":"update"}                           update over Wi-Fi now (allowed with the engine idling, never moving); 2.4+ answers with upd
{"c":"obdscan"}                          try every OBD protocol (headers on) and report who answers and what they offer (2.5+)
{"c":"codes","p":"32","clear":0}         read trouble codes on each protocol listed (clear 1 = also clear them, refused while moving) (2.7+)
{"c":"watch"}                            (relay) Heep is showing Live: send live numbers for the next 90 s, even parked (2.4+)
{"c":"wifi"}  /  {"c":"wifi","scan":1}   send wifi (2.1+); with scan: Wi-Fi on for a minute, scan, join one of yours
{"c":"ota","do":"begin","size":N,"sha":"<SHA-256 hex>","v":"2.2"}   update over Bluetooth (2.1+, Bluetooth only): see below
{"c":"cfg", ...settings...}              see below
{"c":"cfgreset"}                         settings back to new (Wi-Fi and links kept)
{"c":"scr","i":0,"n":10,"d":"<screen text>"} ... then {"c":"scrok","n":10,"h":"<fingerprint>"}   replace all screens
{"c":"getscr"}                           send the screens the T3 has
{"c":"scrdef"}                           back to the default screens
```

**Settings (`cfg`)**, any subset: `wifi` [name, password, ...] · `u` `k` sheet link and key · `tru` `trk` track store link and key ·
`obd` iCar name · `fc` `dc` fuel/distance correction (1.0 = none) · `ss` screen off after s (0 never) · `pk` trip ends after parked s ·
`br` `bn` day/night brightness 0–2 · `nf` `nt` night from/to hour (nf -1 = never) · `tz` minutes from UTC · `sp` key-on screen ·
`lw` live over Wi-Fi (with `"lwu":1` only until the next restart, 2.7+; a new version switches it back on) · `spd` speed source 0 auto 1 iCar 2 GPS · `hm` heading min km/h · `h16` 16 points · `hh` keep heading when stopped ·
`tf` outside °F · `etf` coolant/intake °F (default on) · `opr` OBD protocol (0 auto) · `to` probe correction °C · `gb` GPS baud (0 auto) · `li` `lis` log every s (driving/parked) · `lfl` write to card every s ·
`sdm` make room above % · `rot` screen upside down · `rf` redraw ms · `bm` buttons "short,long;short,long;short,long" · `io4` 0 probe 1 push button.

**`wifi`** (2.1+) what Heep's Wi-Fi page shows:
`{"t":"wifi","fw":"2.1","state":"couldn't join Home: wrong password?","on":false,"ssid":"..","rssi":-58,"ch":6,"ip":"..","onFor":120,`
`"scanning":false,"scanAgo":4,"seen":[["Home",-58,6,0],...],"saved":["Home","Bens iPhone"],"last":{"ssid":"Home","res":"wrong password?","reason":15,"ago":4},...}`
`seen` = [name, dBm, channel, open 1/0], strongest first, from the T3's last scan. `reason` is the ESP-IDF disconnect reason
(15/202/204 password, 201 not found, 210 security not supported). When none of the saved networks is in a scan, the T3 still asks
for one by name (a different one each time): iPhone hotspots often stop showing in scans while they still let known devices join.

**`obdscan`** (2.5+) `{"t":"obdscan","start":true,"n":6}`, then per protocol `{"t":"obdscan","i":1,"n":6,"p":"5","a":"<answer to 0100>",
"b":"<0120>","c":"<0140>","d":"<ATDPN>"}` (raw, headers on: the bytes before `41 00` name the computer that answered), then `{"done":true}`.
Setting `opr` (0 auto, 1-9 ELM327 protocol numbers) fixes the protocol the T3 uses.

**`codes`** (2.7+) `{"t":"codes","start":true,"n":2,"clear":0}`, then per protocol `{"t":"codes","i":0,"n":2,"p":"3","a":"<answer to 0101>",
"b":"<03: stored>","c":"<07: pending>","x":"<04: clear>"}`, raw with headers on and one adapter line per `/`, then `{"done":true}`.
Heep decodes them (`codes.js`): K-line / J1850 `48 6B <computer> 43 <3 codes> <checksum>`, CAN `7E8 <PCI> 43 <count> <codes>`.

**`upd`** (2.4+) progress of an update over Wi-Fi, over Bluetooth and the relay, about every second while it changes:
`{"t":"upd","phase":"wait|check|download|done|fail|current","pct":42,"v":"2.5","text":"downloading 2.5","fw":"2.4"}`.
`done` comes just before the T3 restarts into the new version; `fail`/`current` stay for a minute.

**The relay from 2.4:** the T3 stays connected whenever it's on Wi-Fi with "Live over Wi-Fi" on, and publishes `live` once a second
while driving, for 10 minutes after key-on, and for 90 s after each signed `watch` (Heep sends one every 30 s while Live is open).
The relay connection is made in its own task, so a slow hotspot never freezes the screen.

**Update over Bluetooth** (2.1+, `firmware/T3/otarx.h`, `ota.ino`, app `t3net.js`). After `begin` the T3 answers
`{"t":"ota","ok":true,"ready":true,"chunk":182,"ack":4096}` and from then on reads **every write** as a program packet:
`[offset: uint32 little-endian][up to chunk-4 bytes]`. It answers `{"t":"ota","got":<bytes>}` every 4 KB, `{"t":"ota","need":<offset>}`
when a packet went missing (Heep goes back there), and at the end `{"t":"ota","done":true,"v":"2.2"}` (SHA-256 and the ESP32's
own image check passed) before restarting into it, or `{"t":"ota","ok":false,"why":"..."}`. Heep keeps at most 16 KB ahead of
the last `got`, and goes back to it if the T3 goes quiet for 3 s. Four 0xFF bytes cancel. Nothing arriving for 15 s, or
Bluetooth dropping, cancels too; the T3 keeps its program. A new program gets the same 20 s to prove itself as a Wi-Fi update.

**Screen text** is described at the top of `firmware/T3/screens.h`. The fingerprint is FNV-1a (32-bit, lower-case hex)
of all screens joined with `\n`.

## Trips to the sheet

With trips waiting, the T3 looks for a saved network and sends them straight to the sheet as `put` operations on the
trip tab with the same ids Heep uses, so a trip that arrives both ways is only kept once.

## Tracks to the track store

See the top of `tracks/TrackStore.gs`: `part` (100 CSV rows, can be resent), `fin` (all parts, row count checked), then
the trip is listed in `index.json`. Heep uses `list`, `get` and `del`.
